# Skill gotchas (one line each: reference file, then the fact)

- platform-psp.md: the EBOOT dump (`DumpFileTypes = 7`) does not happen with PPSSPPHeadless via `emu.py --memstick DIR` + `DIR/PSP/SYSTEM/ppsspp.ini`; the windowed PPSSPPWindows64.exe (portable `tools/ppsspp/memstick/`) dumped it within 25 s of launch.
- platform-psp.md: showgim.py only reads `work/gim/<id>.gim` and dies with `max() iterable argument is empty` when nothing matches (also on `--help`); this repo uses its own `tools/gimsheet.py` for numbered survey sheets over any folder.
- platform-psp.md: Atlus PSP (this game) CROW.PAK is not CPK: own dir/file-record archive, nested .pak of the same format, `.zdv` = 16-byte header + zlib (csize 0xFFFFFFFF = stored). Notes in docs/re/pak.md.
- platform-psp.md: PPSSPP has no Lua, but the WebSocket debugger's `cpu.breakpoint.add` + `cpu.runUntilTime` gives Lua-like hooks: a breakpoint stops runUntilTime early (cpu.stepping before the target time), regs via `cpu.getAllRegs` (GPR category has pc), `memory.write` (base64) pokes. Resuming from a breakpoint does not re-hit it. This repo's `tools/debug/pspdbg.py` (Session.play with an on_bp callback) is a candidate for the skill's psp.py.
- platform-psp.md: disassemble a PSP EBOOT from a RAM dump of the loaded module (`hle.module.list` gives base 0x08804000 here), not the ELF: the ELF's pointers are unrelocated, so xrefs on the file miss.
- platform-psp.md: this game's save DATA.BIN is encrypted (SAVEDATA_PARAMS); a save editor can poke RAM after an in-game load and re-save through the game's menu instead of reimplementing the crypto.
- platform-psp.md: PPSSPPHeadless takes `--appendconfig=FILE`: an ini with `[SystemParam] EncryptSave = False` makes PPSSPP write (and load) plain savedata, so a save editor needs no PSP savedata crypto (supersedes the RAM-poke plan above). psp.py/emu.py: pass it with `--emu-arg=--appendconfig=...`; emu.py has no --emu-arg passthrough.
- platform-psp.md / emulator-qa.md: psp.py `--sav DIR` (seed_saves) names the save folder after DIR's basename when DIR holds PARAM.SFO; a copy in a differently named folder is invisible to the game (looked like a checksum failure). Pass the parent folder, or keep the game's folder name.
- emulator-qa.md / psp.py: a route key outside psp.BUTTONS (`l`, `r` instead of `ltrigger`, `rtrigger`) makes emu.py exit 2 with no message and no output dir; `--sheet` output piped to /dev/null hides it completely.
- platform-psp.md: Atlus script loaders can start mid-file: here the first block index is a ctx field read right after the file loads; poking it from a breakpoint (warp.py `block=N`) opens shops/trades whose blocks hold only the command.
- platform-psp.md: PPSSPP memory breakpoints work over the WebSocket API (`memory.breakpoint.add` address,size,read/write); a read watch on a save buffer offset finds the code that copies/verifies it. This repo: tools/debug/watchw.py, bplog.py.
- references/platform-psp.md: PPSSPPHeadless --log shows sceIoOpenAsync paths and kernel warnings; a stale 'Wrong object type for 294, was Mutex, should have been Semaphore' after a savestate load shows from the first frames on, so it is not by itself a sign of the hang you are chasing. IoFileMgrForUser stubs can be found from the import table (lib name ptr -> nid/stub arrays) in a RAM dump.
- emulator-qa.md / platform-psp.md: after a savestate load, PPSSPPHeadless debugger sessions stop at pc=0x08A043B4 (ra=0x08000020) once per frame for a few frames; a breakpoint callback must check r['pc'] against its own addresses, and a hit counter (bplog --max) gets eaten by these stops.
- emulator-qa.md §Debug tool: a field/menu state machine with a jump table can be warped by writing its state word and row index from a breakpoint on its update function (this repo: warp.py `room=N` enters a city location). Cheaper than finding the unlock flags for a destination.
- references/pipeline.md §Extract: player-visible text can sit in a script's sibling data file, not the script (here the choice menus are 0x01 + 30-byte slots in .ksf, first noted as debug labels); before closing extraction, scan every file type for kana runs of 3+ chars and account for each hit.
- references/pipeline.md §Extract: string-pointer columns in table formats can also point at binary blobs (CSVB SSCR scripts here); filter per string (exact decode, no control bytes) and pin the leftover Japanese count per file in the coverage test instead of a blanket skip.
- references/platform-psp.md: the decrypted EBOOT ELF is a relocatable module; the loader rewrites every word with a relocation entry (jal/j, lui/addiu of addresses), so code patches must leave those words alone (reuse an existing j/jal, change only its target). A patcher that refuses relocated words (here tools/eboot.py) catches it up front. PPSSPP boots the plain patched ELF as EBOOT.BIN.
- references/pipeline.md §Marker: Japanese games may draw dialogue vertically (tategaki); find the drawer with a read watch on the font file in RAM, look for a horizontal sibling drawer, and check whether the message system gives each line its own canvas (here max 3 lines, x - 32 per line) before planning line limits.
- SKILL.md ground rules: with context-mode, disasm.py output over ~4 KB comes back as a stub; write the disassembly to a file and Read it in parts.
- references/pipeline.md §Marker: tategaki engines run a punctuation -> vertical-form replace pass over the text before drawing (here 38 SJIS pairs: - = ~ !! !? become rotated glyphs); English stand-ins hit it, so dump and disable that table early; the torture line found it.
- references/pipeline.md §Marker: marker lines at full box width can overflow per-file limits (pwx u16 offsets in 4-byte units = 256 KB here); size marker lines to the JP line's pixel width and test full width with single-string --qa overrides instead.
- references/emulator-qa.md: PPSSPPHeadless with the debugger can die outright (WebSocket closed, empty log) on a game-side overflow instead of reporting an exception; bisect with --qa overrides, one suspect string per build.
- references/platform-psp.md: in a PRX EBOOT the relocation sections list every absolute pointer (R_MIPS_32 words, HI16/LO16 pairs), so EBOOT strings can be repacked into freed room by retargeting those words; change only the lo16 and keep the target inside the lui's window *after* the load base (0x08804000 carries into hi). Growable table files still hit fixed per-screen text buffers (a 160-byte notice buffer here): cap stress strings at the original column maximum.
- references/emulator-qa.md (Windows): a warp spec used as a scene name with ':' in it (mash=N:keys) becomes an NTFS alternate data stream when written as a state file name; name scenes, don't pass raw specs.
- references/platform-psp.md: keystone (MIPS32) rejects absolute branch targets at 0x08xxxxxx ("Invalid operand") and pads `b` with a nop; encode `beq $0,$0` by hand (`.word 0x10000000 | (target - (pc+4)) >> 2`).
- references/platform-psp.md: growable CSVB/system text columns mix short labels and long notices; a label's buffer can be ~40 bytes while its column max is 147: cap stress strings per row (here 3x the JP bytes, min 16), not per column.
- references/pipeline.md (Marker): the marker/long builds replace whole spans incl. player-name codes ({px}), so name splicing is never exercised; an ASCII default name / EBOOT character table crashed the first {px} line only in the real English build. Warp a {px} line in the en build before phase 7 is called done.
- references/emulator-qa.md: a full disk (many 1.3 GB test ISOs) made PPSSPP warps die with 'closed the WebSocket' and an empty log; check free space and delete probe ISOs after each run.
- references/platform-psp.md: when a relocatable PSP module's string pool runs out, add a PT_LOAD segment past .bss (free phdr slot before the first segment's data, file data appended, relocations untouched: R_MIPS_32 words just get target - base); data-word-only strings move there, lo16-bound ones must stay in their hi window. PPSSPP boots it; hardware/signing unverified.
- references/emulator-qa.md: PPSSPP headless exits silently on a guest crash (EOF on the WebSocket, empty log): find the crash site by breakpointing the text pipeline's functions and keeping only the last hits with the strings they hold (this repo's tools/debug/bpstr.py); bisect the text with `--only` + `--qa` single-string builds first.
- references/platform-psp.md (scripts/gim.py): `encode(repalette=None)` re-quantizes the whole atlas when one antialiased label misses the palette by >48, banding every other picture in it (title city/glow art); this repo passes `repalette=False` (tools/gfx.py).
- references/graphics.md §Parallel redraws: graphics agents ran ~280k tokens each for 6-26 rows; stacked one-glyph atlas cells (a ー cell shared by two words) and right-to-left sprite order on title cards need in-game checks the offline brief can't make.
- references/platform-psp.md: new MIPS code in a PRX EBOOT: keystone puts a nop in every branch delay slot itself (don't write your own); reach it by retargeting an already-relocated `jal` (target field = vaddr, the loader adds the base) and address data/return jumps PC-relative (`bal`), so no new relocations are needed; HI16/LO16 pairs are relative to the reloc's segment, so a `lui 0x76; lw 0x2c18` global is NOT LOAD + 0x762C18 (read the live pointer instead).
- references/emulator-qa.md: savestates carry code, so a warp chain `from=` an older state tests the old engine; delete the tag's state dir after an engine change.
- references/translation.md: English can trip latent game bugs JP never reached (here: two player-name codes past byte 32 of one message looped the splice and overflowed). Lint can't see these; warp every line form with name codes in the real en build.
- references/emulator-qa.md: before chasing a visual-QA finding, replay that scene on the current build (same mash, same frames): one "engine" finding (ADV re-wrap) existed only in the stale toured ISO.
- references/platform-psp.md: a speaker-name lookup strncpy'd the name into a 29-byte stack buffer just below saved $s0; long English names clobbered $s0 silently (wrong plate) or fatally (crash). When a length limit "crashes at N", look for a fixed stack buffer next to saved registers; moving the save slot to unused frame padding is a 4-word fix.
- references/platform-psp.md: moving a clobbered saved register out of an overflowing stack buffer is half the fix: check the buffer's zeroing loop and NUL too (the speaker lookup zeroed only 29 bytes, strncpy adds no NUL, so 15+ char names matched nothing and a later {px} line crashed). Verify a stack fix with a full cold-boot run of every scene the name appears in, not one frame.
- references/emulator-qa.md: a warp/tour crash (PPSSPP closes the WebSocket) after an engine change: bisect by checking out the previous tools/engine.py, then bpstr.py on the suspect function's entry and return sites with --regs v0 gives the last values before the crash in one run.
- references/platform-psp.md: fixed-layout screens often place each label with an immediate (`addiu $a1, $zero, X` before the label maker call): scan the init function for the maker jal and rewrite the x immediates per English width at build time; no stub needed. Also: a warp state made from an older build keeps the old code for screens built after the load (delete the whole tag dir, not just the scene state).
- references/pipeline.md (§Extract): a lone-SJIS-char rule (refs > 0, all bytes >= 0x80) misses one-char UI strings: 円 (second byte 0x7E), an unreferenced char[24] array member (瞬) and one whose lui/addiu pair the scan never matched (装); grep the build shots for leftover kanji and pin those offsets in the extractor.
- references/platform-psp.md: a box that wraps by itself every N bytes (help panel: 38) breaks English mid-word; store the English pre-wrapped under N per column (batches.TABLE_WRAP) instead of patching the wrapper.
- references/graphics.md (§Lettering): a word the game builds from repeated cells (ゲーム|オ|ー|バ|ー reuses one ー cell three times) can't take English by redrawing cells: patch the sprite layout (.g2d quad uv -> free cells of the atlas, original bytes checked) and slice one English line over the quads. Also: size labels to the .g2d cell, not the atlas's empty space (k_phon_set Voice Volume cell is 64 px, the label had 66).
- references/translation.md (§Batches): a table column often feeds several boxes, so its longest JP line is no box width; English for a multi-line JP entry should keep the JP's line count (balanced) when one line would be wider than the JP's own longest line.
- references/graphics.md (§Survey) / platform-psp.md: a GIM survey over *.gim files misses textures embedded in 3D model files (.znt here: 1,091 unique GIMs, incl. a whole UI questionnaire sheet). Scan every file for the MIG.00.1PSP magic (size = u32 at +0x14 + 0x10) and survey those too; splice edits back in place at the same size.
- references/platform-psp.md (movies): a PMF can take a re-encoded H.264 stream without re-muxing: keep every pack, PES header, timestamp and 0xBF table and overwrite only the 0xE0 payload bytes, with each new access unit (x264 aud=1, same keyframes via -force_key_frames expr:eq(n,K)+..., -bf 0, SEIs stripped by filter_units=remove_types=6) padded to the original AU size with a filler NAL; lower crf until no frame is bigger. Frames without changes must be passed through unchanged or tiny black frames (38 bytes) overflow. No backslash before the comma in the expr when ffmpeg is called without a shell. (tools/pmf.py here)
- references/graphics.md (§Survey) / platform-psp.md: the EBOOT can carry its own zdv/zlib copy of a CROW.PAK texture (the loading strip here, ELF 0x2A6918), so the archive redraw never shows; when a redrawn label still shows Japanese on a cold boot, dump RAM, match the GIM pixels, and scan the ELF for zlib streams (78 9c/78 da) that inflate to it. Recompress the English into the same slot.
- references/platform-psp.md (movies): ffmpeg's `-force_key_frames expr:eq(n,..)+..` fails ("Invalid force_key_frames expression", ENOMEM) past ~130 keys, and x264's qpfile is not a libx264 param: pass a comma list of times (n*1001/30000 - 0.005) instead.
- references/platform-psp.md (movies): x264 repeats SPS/PPS before every IDR in a raw .264, so with IDR-only keyframes the GOPs are independent: keep the original access units of GOPs nothing was drawn on and pick the crf per GOP (one 239-byte original frame otherwise forced a whole movie to crf 30).
- references/graphics.md (movies): scrolling credits: measure the constant scroll (sub-pixel, frames n and n+200), stitch the roll from frames where each row sits on a whole pixel, find text runs there; per frame erase inside the shifted boxes and stamp pre-rendered English with a sub-pixel blend. The same roll in several movies: match runs by box after the y offset most pairs agree on (tools/credits.py).
- references/graphics.md (movies): sliding credit cards: find each card where it holds still (successive-frame NCC > 0.97 on its side of the screen), take runs from the hold's brightest frame, then follow it out frame by frame with a 1-D FFT correlation along x over its text rows (normalize by the frame energy under the ref's support; zero faint ref pixels first or the score exceeds 1); a max-over-time mask is smeared by the slide and useless.
- references/translation.md (TSV): Python csv.reader on a TSV with default quoting strips "..." around a whole field ("Kirifuda" -> Kirifuda); read and write with quoting=csv.QUOTE_NONE.
- references/emulator-qa.md (Visual QA): in Orca runs `codex exec` is the only independent reviewer; it can hit a ChatGPT usage limit mid-run (worker 16: blocked until a date two days out), so a review plan that depends on it needs a fallback (review chunks yourself across workers).
- references/graphics.md (survey): a GIM-only survey misses plain image files in the archive (PSP save dialog's new-data icon was a .png in CROW.PAK); list every file extension in the unpacked tree and check each image type.
- references/platform-psp.md (code stubs): PSP relocatable EBOOT: a lui/addiu pair naming .data/.bss relocates relative to its segment (seg1 vaddr added), so RAM = load base + seg1 vaddr + value, not base + value; read the relocated pair back from the emulator before hard-coding a data address in a stub (a wrong one read garbage and crashed at first use).
- references/platform-psp.md (text): readability over bright art: draw the text again in black at small offsets before the real draw (set GE material ambient 0x55/0x58 through the game's own list pointer, restore after); 3 passes (1,0) (0,1) (1,1) kept words legible over white windows where one (1,1) pass did not.
- assets/visual-qa-brief.md (dispatch): parallel visual-qa agents writing helper scripts to the shared session scratchpad overwrote each other's (strip.py); tell each agent to use its own subfolder (scratch/<chunk>/).
- assets/visual-qa-brief.md (save dialog): the PSP system save dialog shows the game's savedata title on one line (~44 chars); a long translated title runs off screen: check it in a stress-save tour.
- references/platform-psp.md (psp.Run memstick): psp.py wipes the memstick only when none is passed; a harness passing its own path keeps an earlier build's save, and the save dialog then shows that save's stale PARAM.SFO title. Wipe the per-run memstick in the harness.
- references/emulator-qa.md (warp from= states): a scene warped `from=` another scene's savestate runs the code in that state, so after a rebuild delete the whole tag's states, not only the scene's own.
- references/graphics.md (3D textures out of reach): when a textured room can't be walked to, a RAM search at a savestate in the room for 32 bytes of the new GIM (and the old bytes absent) proves the game loaded it.
- references/platform-psp.md (finding a UI draw): a menu label set once at screen open is missed by breakpoints armed after a warp lands; arm them from boot and print only once the warp fired (tools/debug/bpscene.py). Each plate can have its own copy of the draw code (the quest shop's money plate shares nothing with the menu's): grep the EBOOT for loads of the value's field (money 0xbd4) to find every copy.
- references/emulator-qa.md (long tours): the host's memory reaper can kill a 70-scene tour midway; make the tour resumable (skip scenes whose end state exists) instead of restarting it.
- references/platform-psp.md (capstone): a scratch script named dis.py shadows the stdlib `dis` that capstone imports via inspect (circular import error); name it otherwise. Unrelocated EBOOT jal targets are vaddrs: add LOAD (0x08804000) before setting a breakpoint.
- references/pipeline.md (Release, jp_left): a CSVB-style table whose English is appended and repointed leaves the old Japanese unreferenced in the pool, so `jp_left --orig` floods; scan only the strings the table's pointers reach (release.py step jp). That scan found two live strings the extractor missed: a cp932 IBM-extension kanji (FB5E) that fails the round-trip check, and an EBOOT string preceded by a struct byte instead of NUL.
- scripts/ (pairs-style tools): a script that takes OUT as its first positional arg turns `--help` into a file named `--help`; handle -h first.
- references/translation.md (Review, story pass): the first 15 part-reviewers kept reporting the same game-wide voice drifts (a character's sentence-final tic dropped, dialect flattened to the lead rough boy's, まったく = "Honestly" for everyone, female characters called "he"). Better to sweep them once by speaker + JP marker (tools/voice_scan.py: speaker, JP regex, EN regex), one agent per voice, and list the queued items in later reviewers' dispatches so they don't report them again. Mechanical ones ("......", " -- ", a fixed tag) go straight to an out.tsv that `batches.py merge` takes.
- tools/ (release script): assets/skill.py exports SCRIPTS as a str, so a release.py that does `SCRIPTS / "emu.py"` crashes at the first step that calls a skill script; wrap it in Path (or make skill.py export Paths).
